# ADR-202609131805: Seleksi Arsitektur Integrasi Graphify (JIT MCP vs Universal Eager Hook)

- **Tanggal**: 2026-09-13
- **Status**: Accepted
- **Pengambil Keputusan**: LLM Council (The Contrarian, First Principles, Expansionist, Outsider, Executor)
- **Kategori**: Architecture
---

## 1. Konteks & Masalah (ELI5)
Ibarat memiliki mesin rontgen / X-Ray canggih: alat ini sangat hebat untuk melihat tulang yang patah tanpa operasi bedah. Namun, jika dokter memaksa pasien masuk ke tabung rontgen setiap kali hendak makan siang, minum obat, atau menyisir rambut, pasien akan kelelahan dan rumah sakit bangkrut karena listrik boros.

Pengguna mengusulkan untuk menambahkan instrumen `graphify` (pembuat peta relasi kode / knowledge graph) secara otomatis pada setiap pemanggilan skill utama di ekosistem Pero. Perlu diputuskan apakah otomatisasi ini layak dipasang sebagai middleware universal atau melalui pendekatan selektif (*Just-In-Time*).

## 2. Faktor Pendorong Keputusan (*Decision Drivers*)
- **Latensi Eksekusi**: Siklus TDD mikro membutuhkan loop balik 5-10 detik; pemindaian graf penuh pada setiap langkah memicu macet (*freeze*).
- **Efisiensi Konteks AI**: Memuat seluruh AST kode pada tugas non-kode (PRD, formatting) memicu penurunan fokus kognitif (*Lost-in-the-Middle*).
- **Prinsip YAGNI & Anti-Slop**: Kode belum ada di tahap hulu; pemindaian repositori kosong adalah pemborosan sumber daya.

## 3. Opsi yang Dipertimbangkan
- **Opsi 1: Eager Universal Hook**
  - *Kelebihan*: Graf selalu terbarukan di setiap detik.
  - *Trade-off / Kekurangan*: Bencana latensi I/O, boros token, tidak relevan untuk skill teks/konsep.
- **Opsi 2: Selective Just-In-Time MCP Integration (Dipilih)**
  - *Kelebihan*: 0 latensi pada alur harian, kapabilitas graf aktif tepat saat arsitektur & tracing dibutuhkan.
  - *Trade-off / Kekurangan*: Memerlukan aturan pemicu yang jelas di `AGENTS.md`.

## 4. Keputusan Final & Rationale
Dipilih **Opsi 2 (Selective Just-In-Time MCP Integration)**.
Opsi 1 ditolak mutlak karena melanggar prinsip anti-slop dan merusak performa harian pengembang.

## 5. Konsekuensi Teknis
- **Dampak Positif**: Siklus koding dan perbaikan teks tetap secepat kilat; perkakas X-Ray dependensi tersedia via server MCP `graphify`.
- **Trade-off Negatif**: Pembaruan graf tidak otomatis berjalan jika kode dimodifikasi di luar sesi.
- **Strategi Mitigasi**: Pemicu eksplisit diwajibkan pada fase Brownfield (`pero-system-architecture`), audit dampak (`pero-change-management`), dan penelusuran bug (`systematic-debugging`).
