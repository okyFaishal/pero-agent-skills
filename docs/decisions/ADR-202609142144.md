# ADR-202609142144: Integrasi CONTEXT7_API_KEY dengan Pagu Adaptif dan Pertahanan Jalur Cadangan

- **Tanggal**: 2026-09-14
- **Status**: Accepted
- **Pengambil Keputusan**: Pengguna & Antigravity (Sintesis Sidang LLM Council 5 Penasihat)
- **Kategori**: Architecture
- **Relasi**: None

---

## 1. Konteks & Masalah (ELI5)
Sebelumnya, server MCP Context7 dijalankan dalam mode anonim tanpa kunci akses (*zero-key baseline*). Dalam mode ini, kuota dibatasi berdasarkan alamat IP publik komputer sehingga rentan terkena pembatasan kuota (*rate limit*) jika jaringan internet digunakan bersama. Di sisi lain, pembatasan kaku maksimal 3 pemanggilan per sesi masalah terkadang dirasa sempit saat meriset pustaka besar. Pengguna mengusulkan untuk memasang kunci API pribadi, menghapus batasan pemanggilan seutuhnya, dan tetap mempertahankan jalur cadangan pencarian web.

Berdasarkan musyawarah 5 penasihat AI (*LLM Council*), menghapus batas panggilan secara total (*unbounded queries*) adalah bahaya fatal yang dapat membanjiri ruang ingatan AI (*context window flooding*), memicu kepikunan instruksi (*lost-in-the-middle*), serta menghanguskan kuota 1.000 panggilan dalam beberapa jam akibat perulangan tak henti (*infinite retrieval loop*).

---

## 2. Faktor Pendorong Keputusan (*Decision Drivers*)
- **Kemandirian Kuota**: Membutuhkan kuota bulanan independen (1.000 request/bulan) yang terpisah dari IP publik jaringan.
- **Integritas Penalaran AI**: Menjaga jendela konteks agen agar tidak tenggelam oleh tumpukan teks dokumentasi mentah ribuan baris.
- **Efisiensi Anggaran Token & Latensi**: Mencegah pemborosan token dan latensi round-trip npx yang memperlambat respons AI.
- **Keamanan Kredensial**: Menjaga agar kunci rahasia tidak pernah tertulis terbuka di repositori (*env-guard*).

---

## 3. Opsi yang Dipertimbangkan
1. **Opsi A (Usulan Awal Pengguna - Kunci API + Tanpa Batas Panggilan)**:
   - *Kelebihan*: Kebebasan eksplorasi tanpa rasa terkekang kuota per sesi.
   - *Trade-off / Bahaya*: Membakar kuota dalam sekejap, distorsi penalaran model akibat banjir token, dan risiko kebuntuan saat terjadi kegagalan pencarian berulang.
2. **Opsi B (Status Quo - Tanpa Kunci + Batas Kaku 3 Panggilan)**:
   - *Kelebihan*: Zero-setup, hemat token.
   - *Trade-off / Kekurangan*: Berebut kuota IP publik, batasan 3 panggilan terlalu sempit untuk modul kompleks.
3. **Opsi C (Vonis Dewan Terpilih - Kunci Terproteksi + Pagu Adaptif Maks 5 + Penghentian Dini)**:
   - *Kelebihan*: Kuota mandiri via `CONTEXT7_API_KEY`, batas fleksibel hingga 5 panggilan untuk tugas besar, otomatis berhenti begitu tanda tangan fungsi ditemukan, dan jalur cadangan (*fallback*) tetap aktif.
   - *Trade-off / Kekurangan*: Agen tetap memiliki batasan maksimal (tidak bisa merayap seluruh dokumentasi layaknya web crawler).

---

## 4. Keputusan Final & Rationale
Dipilih **Opsi C (Pagu Adaptif Terukur dengan Kunci Terproteksi)** karena:
- Mengamankan kuota privat akun pengguna tanpa risiko pembakaran kuota tak sadar.
- Melindungi daya nalar model AI dari fenomena *context suffocation* dan *lost-in-the-middle*.
- Menjamin kelangsungan kerja berkat alur cadangan otomatis ke pencarian web terarah jika kuota bulanan habis.

---

## 5. Konsekuensi Teknis
- **Dampak Positif**: Akses dokumentasi resmi lebih stabil, terhindar dari galat kuota IP publik, dan agen tetap disiplin merumuskan kueri spesifik.
- **Trade-off Negatif**: Memerlukan variabel lingkungan `CONTEXT7_API_KEY` di berkas `.env`.
- **Strategi Mitigasi**: Jika `CONTEXT7_API_KEY` kosong atau belum diisi pengguna, sistem otomatis melakukan fallback tanpa galat ke mode anonim atau jalur pencarian web resmi via skill `web-search`.
