# ADR-202609142226: Perampingan Ekosistem Tooling Penelusuran Web dan Pengendalian MCP

- **Tanggal**: 2026-09-14
- **Status**: Accepted
- **Pengambil Keputusan**: Pengguna & Antigravity (Sintesis Sidang LLM Council 5 Penasihat)
- **Kategori**: Architecture
- **Relasi**: Melanjutkan ADR-202609142144

---

## 1. Konteks & Masalah (ELI5)
Sebelumnya, berkas konfigurasi `.mcp.json` memuat hingga 8 server MCP sekaligus, termasuk beberapa perkakas yang fungsinya saling tumpang-tindih (seperti `fetch`, `puppeteer`, `brave-search`, dan `google-stitch`). Menjalankan banyak server MCP berbasis Node.js/Chromium di latar belakang memboroskan memori RAM komputer (ratusan MB) dan mengotori jendela ingatan AI (*context window*) dengan instruksi perkakas yang jarang dipakai. 

Pengguna mengusulkan untuk mengandalkan perkakas bawaan resmi Antigravity (`search_web` dan `read_url_content`) yang berjalan instan tanpa membebani komputer lokal, didampingi dua MCP spesialis berdaya tinggi (`tavily` untuk riset mendalam AI dan `chrome-devtools` untuk inspeksi antarmuka peramban), sembari memangkas seluruh MCP yang redundan.

---

## 2. Faktor Pendorong Keputusan (*Decision Drivers*)
- **Pembersihan Alat Berlebih (*Anti-Slop & Tool Bloat Elimination*)**: Menghilangkan duplikasi alat yang fungsinya serupa agar agen AI tidak mengalami kebingungan pemilihan alat (*tool selection ambiguity*).
- **Efisiensi Memori RAM & CPU**: Mematikan proses latar belakang Puppeteer dan server Node.js yang tidak terpakai.
- **Penghematan Ruang Token (*Context Window Optimization*)**: Mengurangi beban token skema JSON alat pada prompt sistem agen.
- **Pemisahan Peran yang Jernih (*Separation of Concerns*)**:
  - Harian / Cepat: `search_web` + `read_url_content` (Nol kuota, nol RAM).
  - Riset Mendalam Multi-Sumber: `tavily` (Rangkuman berorientasi AI).
  - Diagnostik Web: `chrome-devtools` (DOM, console logs, network).
  - Dokumentasi Resmi: `context7` (Spesialis API dan package docs).
  - Peta Pengetahuan Kode: `graphify` (X-Ray AST modul besar).

---

## 3. Opsi yang Dipertimbangkan
1. **Opsi A (Status Quo - Mempertahankan 8 MCP Sekaligus)**:
   - *Kelebihan*: Semua opsi perkakas tersedia.
   - *Trade-off / Kekurangan*: Boros RAM, memicu peringatan error kunci kosong untuk server tak terpakai, membebani context window.
2. **Opsi B (Pangkas Ekstrem - Hanya Menggunakan Bawaan Tanpa MCP Web Sama Sekali)**:
   - *Kelebihan*: Paling ringan.
   - *Trade-off / Kekurangan*: Kehilangan kemampuan inspeksi DOM/Console peramban dan kehilangan kecepatan riset multi-sumber Tavily.
3. **Opsi C (Vonis Dewan Terpilih - Racikan Ramping 4 MCP + Native Duo)**:
   - *Kelebihan*: Keseimbangan sempurna antara efisiensi sumber daya dan kapabilitas teknis tingkat tinggi.

---

## 4. Keputusan Final & Rationale
Dipilih **Opsi C (Racikan Ramping 4 MCP + Native Duo)** karena:
- Menghapus redundansi secara tuntas: `fetch` digantikan `read_url_content`, `puppeteer` digantikan `chrome-devtools`, dan `brave-search` digantikan `search_web`.
- Mempertahankan `tavily` untuk tugas riset yang membutuhkan pembacaan dan penyimpulan puluhan artikel web secara instan.
- Mempertahankan `chrome-devtools` untuk mendiagnosis galat aplikasi web di peramban Chrome.

---

## 5. Konsekuensi Teknis
- **Dampak Positif**: Beban RAM Mac berkurang drastis, prompt sistem lebih bersih dan hemat token, serta alur penelusuran lebih terarah.
- **Mitigasi Portabilitas**: `install.sh` diperbarui agar secara cerdas hanya mendaftarkan MCP yang memiliki kunci aktif atau perintah CLI yang terpasang di sistem.
