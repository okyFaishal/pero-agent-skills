# ADR-202609142238: Pengembalian Google Stitch MCP dengan Karantina Domain UI/UX Penuh

- **Tanggal**: 2026-09-14
- **Status**: Accepted
- **Pengambil Keputusan**: Pengguna & Antigravity (Sintesis Sidang LLM Council 5 Penasihat)
- **Kategori**: Architecture
- **Relasi**: Melanjutkan ADR-202609142226

---

## 1. Konteks & Masalah (ELI5)
Setelah dilakukan perampingan MCP sebelumnya, pengguna menghendaki pengembalian server MCP Google Stitch (`@_davideast/stitch-mcp`) untuk pembuatan prototipe visual nyata di antarmuka web, dengan komitmen bahwa alat ini hanya akan dipakai saat membahas desain UI/UX. 

Sidang 5 penasihat dewan AI (*LLM Council*) sepakat bahwa keberadaan prototipe visual interaktif memberikan kepastian bentuk desain yang tidak bisa digantikan oleh deskripsi teks semata. Namun, untuk mencegah pencemaran konteks (*context bloat*) pada pekerjaan logika dan menghindari kegagalan eksekusi jika kunci API belum disetel, disepakati aturan karantina wilayah kerja (*domain quarantine*) dan jaring pengaman kunci kosong (*graceful fallback*).

---

## 2. Faktor Pendorong Keputusan (*Decision Drivers*)
- **Validasi Visual Nyata**: Memastikan desain antarmuka tervalidasi secara visual (kontras, tata letak, ritme spasial) via Google Stitch sebelum koding dimulai.
- **Karantina Domain (*Domain Quarantine*)**: Membatasi penggunaan Stitch hanya pada Tahap 5 Pero SDLC (`pero-uiux-design`) dan melarang pemanggilan pada tugas backend, basis data, atau CLI.
- **Pengaman Kunci Kosong (*Missing Key Guardrail*)**: Menghindari crash atau error timeout jika pengguna belum mengisi `STITCH_API_KEY` di berkas `.env`.
- **Efisiensi Memori (Lazy Loading)**: Memanfaatkan arsitektur lazy loading Antigravity agar pendaftaran Stitch tidak membebani memori kerja selama tidak dipanggil.

---

## 3. Opsi yang Dipertimbangkan
1. **Opsi A (Menolak Pengembalian Stitch - Desain Murni Teks/Mermaid)**:
   - *Kelebihan*: Konfigurasi minimalis, nol dependensi cloud visual pihak ketiga.
   - *Trade-off / Kekurangan*: Pengguna dan agen harus "meraba-raba" wujud visual dari sketsa teks abstrak.
2. **Opsi B (Mengembalikan Stitch Tanpa Batasan - Terpasang Global Tanpa Guardrail)**:
   - *Kelebihan*: Bebas dipakai kapan saja.
   - *Trade-off / Kekurangan*: Agen rentan memanggil Stitch untuk perbaikan CSS kecil atau bahkan saat memprogram backend, memicu error timeout jika API key kosong.
3. **Opsi C (Vonis Dewan Terpilih - Pengembalian dengan Karantina Domain & Fallback Otomatis)**:
   - *Kelebihan*: Nilai visual diperoleh secara maksimal pada fase desain, memori kerja tetap bersih di fase lain, dan sistem aman dari kegagalan koneksi.

---

## 4. Keputusan Final & Rationale
Dipilih **Opsi C (Pengembalian dengan Karantina Domain UI/UX)** karena:
- Mengembalikan server `google-stitch` ke `.mcp.json` dan `install.sh` dengan variabel `STITCH_API_KEY`.
- Mempertegas aturan di `pero-uiux-design/SKILL.md` bahwa agen dilarang memanggil server Stitch di luar Tahap 5, serta wajib langsung menggunakan sketsa Mermaid/ASCII jika `STITCH_API_KEY` kosong di `.env`.

---

## 5. Konsekuensi Teknis
- **Dampak Positif**: Prototipe visual interaktif kembali tersedia untuk antarmuka pengguna tanpa membebani pekerjaan harian.
- **Strategi Mitigasi**: Jika `STITCH_API_KEY` belum diisi pengguna, agen tidak akan memaksakan koneksi jaringan ke server MCP, sehingga tidak ada error sistem.
